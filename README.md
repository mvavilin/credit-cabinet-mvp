# Умный кредитный кабинет предпринимателя — MVP

**Деплой:** [Открыть приложение](https://credit-cabinet-mvp.vercel.app/)

Минимальный веб-прототип сквозного кредитного процесса для хакатона. Стек: React, TypeScript, Tailwind CSS, Zustand. Внешние банковские интеграции, LLM и платные API не используются.

## Функциональность

- Диалоговый сбор потребности по простым правилам и шаблонам.
- Редактируемый профиль компании и финансовых показателей.
- Два синтетических кредитных продукта и аннуитетный калькулятор.
- Проверка обязательных полей и создание заявки с идентификатором.
- Симуляция внутренней обработки: проверка полноты, формализованные правила риска и 4 результата — одобрение, отказ, запрос данных, альтернативные условия.
- История заявки и сохранение Zustand state в `localStorage`.
- Управление сценариями отказа и запроса документов через чекбоксы финансового профиля.
- Docker-запуск.

## Локальный запуск

Требуется Node.js 20+.

```bash
npm install
npm run dev
```

Откройте URL, который напечатает Vite (обычно `http://localhost:5173`).

## Docker

```bash
docker compose up --build
```

Откройте `http://localhost:8080`.

## Сквозной тест

1. На главной странице отправьте «Нужно 2 млн ₽ на закупку товара».
2. Откройте финансовый профиль и проверьте компанию, ИНН, выручку, расходы и платежи.
3. Для демонстрации одобрения оставьте документы готовыми, просрочки выключенными, выручку выше расходов; свободный поток должен быть не менее 1.3 расчётного платежа.
4. Для запроса данных снимите «Документы готовы».
5. Для отказа включите «Есть просрочки» либо задайте расходы не ниже выручки.
6. Для альтернативных условий задайте положительный поток, но уменьшите его так, чтобы он был ниже 1.3 расчётного платежа.
7. Выберите продукт, перейдите к заявке и нажмите «Отправить заявку».
8. На этапе рассмотрения нажмите «Запустить проверки» и проверьте результат.
9. Обновите страницу: состояние сохраняется в localStorage.

## Ограничения и допущения

Это frontend-only MVP. Zustand/localStorage заменяют backend и базу данных; поэтому данные хранятся только в конкретном браузере. Мок-кредитный движок не является реальным скорингом и не оценивает кредитоспособность по банковским стандартам. Ставки и продукты вымышлены. Одобрение — только симуляция. В реальном продукте бизнес-правила и решения должны находиться на сервере, а статус должен поступать из доверенного процесса обработки.

Для соответствия требованиям сдачи проекта необходимо создать Git-репозиторий, зафиксировать lock-файл (`npm install` создаст `package-lock.json`), выполнить сборку и приложить актуальный commit hash. Не загружайте реальные персональные или банковские данные.
